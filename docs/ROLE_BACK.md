# 백 (서버·데이터·관제) 할 일 — 장정훈

> 문서의 "백 (서버·데이터·관제)" 탭을 옮긴 것이다 (11/11 기준). 규칙과 API·데이터 형식은 루트 `CLAUDE.md`의 공통 규약을 따른다.

백(장정훈)은 데이터 수집, 배차·시뮬레이션 서버, 관제 화면을 혼자 맡는다. 개발 18~23시간 + 버그 수정·발표 파트 4~5시간. 앱이 없어도 브라우저·PowerShell·웹 관제로 끝까지 시험하고, 서버를 push할 때 `server/README.md`에 실행법을 적어 프론트가 혼자 켜서 붙일 수 있게 한다. 막히면 카톡 → 그래도 안 풀리면 그때 만난다.

## 맡는 범위 (교수님: "합승·최적 배차는 서버에서 다 하고, 데이터는 긁어와서 서버에 DB화")

- 데이터: 정류장(서울 열린데이터광장 버스정류소 위치정보 파일 → DB), 지도 이미지 + 좌표 범위, (2주차) 도로 좌표
- `server/`: Node.js + Express. 배차 엔진, 이동 시뮬레이션, API, 실행법·로직 설명(`README.md`)
- `web/`: 웹 시뮬레이터를 참고한 관제 화면을 서버에 연결
- 추가 기능: 내역·취소 API, 클라우드 배포
- 발표·보고서·시연 영상의 서버·관제 파트

## 할 일

### 1주차 (11/12~11/20)

- [ ] **B0. 준비 (1h)**
  - 서울 열린데이터광장(data.seoul.go.kr)의 **"서울시 버스정류소 위치정보"**(OA-15067)에서 가장 최근 파일을 내려받아 `server/data/raw/`에 둔다. 같은 곳의 **"서울시 버스노선별 정류소 정보"**(OA-1095) 최신 파일도 받는다 (정류장마다 서는 N버스 확인용). 파일 다운로드라 인증키가 필요 없다 (공공데이터포털 API 키는 신청하지 않음)
  - 레포 루트에 `server/`, `web/` 폴더 만들기. 웹 시뮬레이터 HTML을 참고용으로 `web/index.html`에 두고 관제 화면의 출발점으로 씀. `.gitignore`에 `node_modules/`, `.env`, DB 파일
  - 웹 시뮬레이터를 읽고 끼워넣기 배차 방식(`attemptInsertGlobal`, `evaluateBusRoute` 등)과 상수를 정리. 서버에서 쓸 함수·데이터 구조를 정한다 (그대로 옮기는 게 아니라 참고)
- [x] **B1. 데이터 수집 스크립트: 정류장 + 지도 (3~4h)** — 교수님: "긁어와서 서버에 DB화", "지도 데이터도 다 받아놓고, 이미지로 받든…"
  - `server/data/area.json`: 시범지역 사각형(north·south·west·east — 북서 태릉입구역 · 북동 봉화산역·신내역 · 남서 상봉역 · 남동 망우역·우림시장)과 시범 정류장 ID 목록(`hubStopIds` 승차 거점 6개 = N버스 서는 역 앞, `homeStopIds` 주거지 19개). 정류장과 지도가 이 범위 하나를 같이 쓴다
  - 노선별 정류소 파일에서 노선명이 N으로 시작하는 심야버스를 골라 정류장마다 `nightRoutes`로 붙인다. 이 범위에는 N13·N26·N61·N72가 지난다. 승차 거점에 N버스가 안 서면 경고
  - `npm run collect`(`server/scripts/collect.js`) 한 번으로 정류장과 지도를 같이 만든다
  - 정류장: `server/data/raw/`의 정류소 위치정보 파일을 읽어 사각형 안 정류소만 `server/data/stops-all.json`으로 뽑는다. 정류소번호(ARS-ID)는 5자리 문자열로 맞추고(앞자리 0이 빠진 4자리면 0을 붙임), 좌표는 WGS84 위도·경도 그대로. 그중 `area.json`에 적은 시범 정류장 25개(승차 거점 6 → 주거지 19 순, 서로 300m 이상 떨어지게)만 `server/data/stops.json`으로. `stops.json`은 공통 규약 `Stop` 형식 그대로(`kind` = HUB/HOME, `nightRoutes` 포함)
  - 지도: 같은 사각형의 OSM 지도 데이터(도로·철도·공원·물·건물)를 Overpass API로 한 번 받아 `server/data/raw/osm-area.json`에 두고, 그걸로 다크 테마 지도를 직접 그려 `server/data/map.png`(2400×2306px)와 `server/data/map.json`(`MapInfo`: 범위 4개 = area.json 그대로, 이미지 크기, 출처)으로 저장. OSM 타일 서버 그림을 미리 받아 두는 건 이용 정책상 금지라 쓰지 않는다. 받아 둔 데이터가 있으면 다시 받지 않는다 (`npm run collect:refresh`로 새로 받기)
  - 확인용 `server/data/map-check.png`: 지도 위에 범위 안 정류장(회색, N버스 서는 곳은 하늘색)과 시범 정류장(파랑 = 승차 거점, 노랑 = 주거지, 옆 숫자 = 순번)을 찍은 그림
  - `raw/` 원본, `stops.json`, `map.json`, `map.png`는 커밋한다 (프론트가 수집 없이 서버를 켤 수 있게). 서버는 시작할 때 SQLite DB(`stops`, `map_info`)가 없으면 이 파일들로 만든다. DB 파일은 커밋하지 않는다
  - 완료 기준: `npm run collect` 후 `stops.json` 좌표가 위도 37.x / 경도 127.x이고, 정류장 몇 개를 공통 규약 5의 식으로 픽셀로 바꿔 `map.png`에 찍었을 때 실제 자리와 맞음
- [ ] **B2. 서버 뼈대 + 배차 엔진 작성 (4~5h)**
  - `server/package.json`, `server/index.js`(Express, 포트 3000, `0.0.0.0`에서 대기), `server/engine.js`(배차·시뮬레이션), `server/db.js`(SQLite)
  - 상태(버스, 승객, 시뮬 시각)는 서버 메모리에, 정류장·지도 정보는 DB에서 읽음. 버스 시작 위치는 시범 정류장 중에서, 버스 대수는 설정값으로
  - 배차는 웹 시뮬레이터의 끼워넣기 방식을 참고 (모든 버스 × 승차·하차 위치 조합을 넣어 보고, 제약을 지키면서 가장 좋은 걸 고름). 제약값은 공통 규약 6 기준: 최대 대기 15분, 기존 승객 지연 5분(웹은 8분), 정원 6명
  - 완료 기준: 테스트 스크립트로 호출을 몇 번 넣으면 배정된 버스와 노선이 출력됨
- [ ] **B3. 탑승 인원 + 서버 시계 (2h)**
  - 웹은 호출 1건 = 1명으로 셌다. 서버는 호출마다 `partySize`를 저장하고 정원 비교를 **탑승 중인 호출들의 인원 합**으로 한다
  - `setInterval`로 1초마다 `tick`. 배속 기본 6 (실제 1초 = 시뮬 6초), 설정 값 하나로 조절
  - 끝난 호출(하차·배차 실패)은 지우지 않고 남겨서 앱이 `COMPLETED`·`REJECTED`를 받을 수 있게
- [ ] **B4. API (2h)**
  - 공통 규약 3 그대로: `/stops`, `/map`, `/map/image`, `POST /calls`, `/calls/{callId}`, `/buses`. `callId`는 `"c-1"`, `"c-2"`…, 404·400 처리, `path`는 일단 `[]`
  - `express.static`으로 `../web` 폴더를 같이 띄움 → 웹 관제 주소 `http://localhost:3000/`
  - 완료 기준 (11/20): 브라우저에서 `/stops`, `/map`, `/map/image`, `/buses`가 보이고, PowerShell에서 `POST /calls`를 보내면 `callId`가 돌아오고, `/calls/{callId}`가 시간이 지나며 바뀜
- [ ] **B4-1. README + 프론트에게 넘기기 (1h, 11/20)**

  - push 후 프론트에게 카톡
